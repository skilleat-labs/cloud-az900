# Lab 01 · 리소스 그룹 만들기

!!! info "실습 정보"
    - **주제**: 리소스 계층 구조 이해
    - **예상 시간**: 15분
    - **배우는 것**:
        1. Azure 리소스 그룹의 역할과 의미
        2. 태그(Tag)를 사용한 리소스 분류 방법
        3. 잠금(Lock)을 통한 실수 방지 방법

---

## 실습 목표

Azure에서 모든 리소스는 반드시 **리소스 그룹** 안에 속해야 합니다.
이번 실습에서는 리소스 그룹을 직접 만들고, 태그 설정과 삭제 잠금 기능을 체험합니다.
이후 실습(Lab 02~05)에서 이 리소스 그룹을 계속 재사용합니다.

---

## Step 1 · Azure Portal 로그인

1. 브라우저를 열고 [https://portal.azure.com](https://portal.azure.com) 에 접속합니다.
2. 강사에게 받은 계정 정보로 로그인합니다.
3. 로그인 후 Azure Portal 홈 화면이 표시되면 준비 완료입니다.

!!! tip "팁"
    처음 로그인하면 "Microsoft Azure에 오신 것을 환영합니다" 팝업이 표시될 수 있습니다.
    **나중에** 또는 **X** 버튼을 눌러 닫아도 됩니다.

---

## Step 2 · 리소스 그룹 만들기

> Azure Portal → 상단 검색창 → "리소스 그룹" 검색 → 만들기

### 2-1. 리소스 그룹 검색

1. Azure Portal 상단 중앙의 **검색창**을 클릭합니다.
2. `리소스 그룹` 을 입력하고 검색 결과에서 **리소스 그룹**을 클릭합니다.
3. 리소스 그룹 목록 페이지가 열립니다.

### 2-2. 새 리소스 그룹 만들기

1. 왼쪽 상단의 **+ 만들기** 버튼을 클릭합니다.
2. 아래 정보를 입력합니다.

| 항목 | 값 |
|------|-----|
| 구독 | 강사가 제공한 구독 선택 |
| 리소스 그룹 이름 | `rg-[본인이름]-lab` (예: `rg-gildong-lab`) |
| 지역 | Korea Central |

!!! warning "주의"
    리소스 그룹 이름은 구독 내에서 고유해야 합니다.
    반드시 **본인 이름**을 포함시켜 다른 수강생과 구분하세요.

### 2-3. 태그 설정

1. 상단의 **태그** 탭을 클릭합니다.
2. 아래 태그를 추가합니다.

| 이름(키) | 값 |
|---------|-----|
| 실습자 | 본인 이름 (예: 홍길동) |
| 환경 | dev |

3. 태그는 리소스를 분류하고 비용을 추적하는 데 사용됩니다.

### 2-4. 검토 및 만들기

1. **검토 + 만들기** 버튼을 클릭합니다.
2. 유효성 검사 통과 확인 후 **만들기** 버튼을 클릭합니다.
3. 몇 초 후 "배포가 완료되었습니다" 메시지가 표시됩니다.

!!! success "완료"
    리소스 그룹이 성공적으로 생성되었습니다.
    **리소스로 이동** 버튼을 클릭하여 이동합니다.

---

## Step 3 · 리소스 그룹 탐색

> 리소스 그룹 개요 페이지에서 주요 기능을 살펴봅니다.

### 3-1. 왼쪽 메뉴 살펴보기

왼쪽 사이드바의 각 메뉴를 클릭하여 기능을 확인합니다.

| 메뉴 | 설명 |
|------|------|
| **개요** | 리소스 그룹 내 전체 리소스 목록 |
| **액세스 제어(IAM)** | 누가 이 리소스 그룹에 접근할 수 있는지 설정 |
| **태그** | 방금 설정한 태그 확인 |
| **이벤트** | 리소스 그룹 내 발생한 이벤트 로그 |
| **배포** | 이 리소스 그룹에 수행된 배포 기록 |

### 3-2. 태그 확인

1. 왼쪽 메뉴에서 **태그**를 클릭합니다.
2. Step 2-3에서 입력한 태그(실습자, 환경)가 표시되는 것을 확인합니다.

### 3-3. 리소스 목록 확인

1. **개요** 메뉴로 돌아옵니다.
2. 현재 리소스 그룹 안에 아무 리소스도 없음을 확인합니다.
3. 이후 실습에서 VM, App Service 등을 여기에 추가할 예정입니다.

!!! tip "팁"
    리소스 그룹은 단순한 폴더가 아닙니다.
    리소스 그룹을 삭제하면 그 안의 **모든 리소스가 함께 삭제**됩니다.
    따라서 실습 정리 시 리소스 그룹 하나만 삭제해도 깔끔하게 정리됩니다.

---

## Step 4 · 잠금 설정해보기

> 중요한 리소스를 실수로 삭제하지 않도록 보호하는 기능입니다.

### 4-1. 잠금 추가

1. 왼쪽 메뉴를 스크롤하여 **잠금** 메뉴를 찾아 클릭합니다.
2. **+ 추가** 버튼을 클릭합니다.
3. 아래 정보를 입력합니다.

| 항목 | 값 |
|------|-----|
| 잠금 이름 | `lock-test` |
| 잠금 유형 | 삭제 |
| 메모 | 테스트용 잠금 |

4. **확인** 버튼을 클릭합니다.

### 4-2. 잠금 효과 확인

1. 리소스 그룹 **개요** 페이지로 이동합니다.
2. 상단의 **삭제** 버튼을 클릭합니다.
3. 리소스 그룹 이름을 입력하고 삭제를 시도합니다.
4. 아래와 같은 오류 메시지가 표시되는 것을 확인합니다.

!!! warning "주의"
    잠금이 설정된 경우 다음과 같은 오류가 발생합니다:
    > "리소스에 잠금이 있으므로 삭제할 수 없습니다."

    이처럼 잠금은 실수로 인한 삭제를 방지하는 안전장치입니다.

### 4-3. 잠금 삭제

1. 다시 **잠금** 메뉴로 이동합니다.
2. `lock-test` 옆의 **삭제(휴지통 아이콘)** 를 클릭합니다.
3. 잠금이 삭제되면 다시 리소스 그룹을 삭제할 수 있게 됩니다.

!!! tip "팁"
    실제 운영 환경에서는 프로덕션 리소스 그룹에 **삭제 잠금**을 필수로 설정하는 것이 권장됩니다.
    읽기 전용 잠금을 설정하면 수정도 불가능하게 막을 수 있습니다.

    이 리소스 그룹은 **Lab 02~05에서 계속 사용**합니다.
    지금은 삭제하지 마세요.

> 최종 정리 방법: 리소스 그룹 → **삭제** → 이름 입력 → 삭제

## 핵심 정리

1. **리소스 그룹은 Azure 리소스의 논리적 컨테이너**입니다.
   모든 리소스는 반드시 하나의 리소스 그룹에 속해야 하며, 그룹 삭제 시 내부 리소스도 함께 삭제됩니다.

2. **태그(Tag)는 리소스 분류와 비용 추적에 활용**됩니다.
   부서별, 프로젝트별, 환경별(dev/prod)로 태그를 붙이면 비용 관리가 편해집니다.

3. **잠금(Lock)은 실수로 인한 삭제나 수정을 방지**합니다.
   운영 환경에서는 중요한 리소스에 삭제 잠금을 설정하는 것이 모범 사례입니다.
