# Lab 01 · 리소스 그룹 탐색하기

!!! info "실습 정보"
    - **주제**: 리소스 계층 구조 이해
    - **예상 시간**: 15분
    - **배우는 것**:
        1. Azure Portal 로그인 및 기본 화면 탐색
        2. 태그(Tag)를 사용한 리소스 분류 방법
        3. 잠금(Lock)으로 실수로 인한 삭제 방지하기

---

## 실습 목표

강사가 여러분 각자에게 **리소스 그룹**을 하나씩 배정해 두었습니다.
이번 실습에서는 포털에 로그인하고, 배정받은 리소스 그룹을 탐색한 뒤
태그와 잠금 기능을 직접 설정해봅니다.

---

## Step 1 · Azure Portal 로그인

1. 브라우저를 열고 아래 주소에 접속합니다.

    **[https://portal.azure.com](https://portal.azure.com)**

2. 강사에게 배정받은 계정으로 로그인합니다.

    | 항목 | 값 |
    |------|-----|
    | 아이디 | `user##@nrkim0615outlook.onmicrosoft.com` |
    | 비밀번호 | `Skilleat2026!` |

    > `##` 자리에 본인 번호를 입력합니다. (예: user01, user02 ...)

!!! tip "팁"
    처음 로그인하면 "Microsoft Azure에 오신 것을 환영합니다" 팝업이 표시될 수 있습니다.
    **나중에** 또는 **X** 버튼을 눌러 닫아도 됩니다.

---

## Step 2 · 배정받은 리소스 그룹 찾기

1. 상단 검색창에 **`리소스 그룹`** 을 입력하고 클릭합니다.
2. 목록에서 본인에게 배정된 리소스 그룹을 찾습니다.

    > 예: user01 → `test01-rg`, user02 → `test02-rg`

!!! warning "주의"
    목록에 리소스 그룹이 보이지 않거나 다른 사람의 리소스 그룹이 보이면
    강사에게 알려주세요. 본인 것만 보이는 게 정상입니다.

3. 리소스 그룹 이름을 클릭해서 **개요** 페이지로 들어갑니다.

---

## Step 3 · 리소스 그룹 구조 살펴보기

개요 페이지 왼쪽 메뉴를 하나씩 확인해봅니다.

| 메뉴 | 설명 |
|------|------|
| **개요** | 포함된 리소스 목록, 위치, 구독 정보 |
| **액세스 제어(IAM)** | 누가 이 그룹에 어떤 권한을 가지는지 |
| **태그** | 리소스 분류를 위한 키-값 레이블 |
| **배포** | 이 그룹에 배포된 이력 |
| **잠금** | 실수로 삭제되지 않도록 보호 |

!!! tip "지금 리소스가 비어 있는 게 정상입니다"
    아직 아무것도 만들지 않았으니 리소스 목록이 비어 있습니다.
    Lab 02부터 이 안에 리소스를 하나씩 채워갑니다.

---

## Step 4 · 태그 추가하기

태그는 리소스에 **메모**를 붙이는 기능입니다.
어떤 팀이 쓰는지, 누구 것인지 등을 기록할 때 활용합니다.

1. 왼쪽 메뉴에서 **태그** 를 클릭합니다.
2. 아래 값을 입력합니다.

    | 이름 (키) | 값 |
    |----------|----|
    | `실습자` | 본인 이름 |
    | `과정` | `AZ-900` |

3. **저장** 버튼을 클릭합니다.
4. 왼쪽 메뉴 **개요** 로 돌아와서 오른쪽 상단에 태그가 표시되는 것을 확인합니다.

!!! success "완료"
    태그가 보이면 성공입니다. 실무에서는 팀명, 프로젝트, 비용 센터 등을 태그로 달아
    청구서에서 부서별 비용을 분리할 때 사용합니다.

---

## Step 5 · 잠금(Lock) 메뉴 살펴보기

잠금은 **실수로 리소스를 삭제하지 못하도록** 막아주는 안전장치입니다.

1. 왼쪽 메뉴에서 **잠금** 을 클릭합니다.
2. 현재 잠금이 없는 빈 목록을 확인합니다.

!!! info "잠금 유형 2가지"
    | 유형 | 설명 |
    |------|------|
    | **삭제** | 리소스 삭제만 방지. 수정은 가능 |
    | **읽기 전용** | 삭제 + 수정 모두 방지. 조회만 가능 |

    실무에서는 운영 환경 리소스 그룹에 **삭제 잠금**을 걸어두는 것이 모범 사례입니다.

## 💡 핵심 정리

| 개념 | 설명 |
|------|------|
| **리소스 그룹** | Azure 리소스를 묶는 논리적 컨테이너. 삭제하면 안의 모든 리소스가 함께 삭제됨 |
| **태그** | 키-값 형태의 메모. 비용 추적, 팀 분류에 활용 |
| **잠금 — 삭제** | 실수로 인한 삭제 방지. 해제하기 전까지 삭제 불가 |
| **잠금 — 읽기 전용** | 삭제뿐 아니라 수정도 불가. 운영 환경 보호에 활용 |
