# Lab 03 · App Service 웹앱 만들기

!!! info "실습 정보"
    - **주제**: PaaS(Platform as a Service) 컴퓨팅
    - **예상 시간**: 15분
    - **배우는 것**:
        1. PaaS 방식으로 웹앱을 OS 관리 없이 배포하는 방법
        2. App Service 플랜과 요금 계층(Free, Basic, Standard)의 차이
        3. IaaS(VM)와 PaaS(App Service)의 실질적인 차이 체감

!!! warning "사전 준비"
    Lab 01에서 만든 리소스 그룹 `rg-[본인이름]-lab`이 있어야 합니다.

---

## 실습 목표

App Service는 Azure의 대표적인 **PaaS** 서비스입니다.
VM(IaaS)과 달리 OS 설치, 패치, 인프라 관리를 Azure가 담당하고
개발자는 **코드**만 올리면 바로 웹앱이 실행됩니다.
이번 실습에서는 App Service를 만들고 기본 웹페이지에 접속해봅니다.

---

## Step 1 · App Service 만들기

> Azure Portal → 검색창 → "App Service" → 만들기

### 1-1. App Service 검색

1. Azure Portal 상단 **검색창**에 `App Service`를 입력합니다.
2. 검색 결과에서 **App Service**를 클릭합니다.
3. App Service 목록 페이지에서 **+ 만들기** 버튼을 클릭합니다.
4. 드롭다운에서 **웹앱**을 선택합니다.

### 1-2. 기본 사항 설정

**프로젝트 세부 정보:**

| 항목 | 값 |
|------|-----|
| 구독 | 강사가 제공한 구독 선택 |
| 리소스 그룹 | `rg-[본인이름]-lab` |

**인스턴스 세부 정보:**

| 항목 | 값 |
|------|-----|
| 이름 | `app-[본인이름]-lab` (예: `app-gildong-lab`) |
| 게시 | 코드 |
| 런타임 스택 | PHP 8.2 (또는 Node.js 18 LTS) |
| 운영 체제 | Linux |
| 지역 | Korea Central |

!!! warning "앱 이름 주의"
    App Service 이름은 **전 세계에서 고유**해야 합니다.
    `app-[본인이름]-lab` 형식으로 입력하면 보통 고유한 이름이 됩니다.
    이름 오른쪽에 녹색 체크 표시가 나타나면 사용 가능한 이름입니다.

    이 이름이 실제 웹앱 주소가 됩니다: `https://app-[이름]-lab.azurewebsites.net`

### 1-3. App Service 플랜 선택

**App Service 플랜** 섹션에서:

1. **새로 만들기**를 클릭합니다.
2. 플랜 이름: `plan-[본인이름]-lab`
3. **확인**을 클릭합니다.

**가격 책정 플랜:**

1. **가격 책정 플랜** 항목에서 **Free F1**을 선택합니다.
2. (기본값이 아닌 경우 **플랜 변경**을 클릭하여 Free F1을 찾아 선택합니다.)

!!! tip "App Service 플랜 요금 계층"
    | 계층 | 특징 | 용도 |
    |------|------|------|
    | Free F1 | 공유 인프라, 60분/일 CPU | 개발/테스트 (무료) |
    | Basic B1 | 전용 인프라, 사용자 지정 도메인 | 소규모 앱 |
    | Standard S1 | 자동 스케일링, 배포 슬롯 | 프로덕션 |
    | Premium P1 | 고성능, VNet 통합 | 엔터프라이즈 |

    실습에서는 **Free F1**을 사용합니다. (비용 0원)

## Step 2 · 배포 완료 및 접속

### 2-1. 검토 및 만들기

1. **검토 + 만들기** 버튼을 클릭합니다.
2. 설정 내용을 검토합니다.
3. **만들기** 버튼을 클릭합니다.
4. 배포 완료까지 **1~2분** 대기합니다.

!!! success "완료"
    "배포가 완료되었습니다" 메시지가 표시되면
    **리소스로 이동** 버튼을 클릭합니다.

### 2-2. 웹앱 기본 페이지 접속

1. App Service **개요** 페이지로 이동합니다.
2. 오른쪽 상단 또는 **기본 도메인** 항목에서 URL을 확인합니다.
   - 형식: `https://app-[이름]-lab.azurewebsites.net`
3. URL을 **클릭**하거나 브라우저 주소창에 붙여넣습니다.
4. Azure App Service의 기본 시작 페이지가 표시되는 것을 확인합니다.

!!! success "완료"
    브라우저에서 기본 페이지("Your web app is running and waiting for your content")가
    표시되면 App Service가 정상적으로 작동하는 것입니다.

## Step 3 · IaaS vs PaaS 차이 느끼기

> App Service 메뉴를 탐색하며 PaaS의 특징을 직접 확인합니다.

### 3-1. 왼쪽 메뉴 탐색

App Service 왼쪽 사이드바의 주요 메뉴를 클릭하여 살펴봅니다.

| 메뉴 | 설명 | IaaS와의 차이 |
|------|------|--------------|
| **개요** | 앱 상태, URL, 플랜 정보 | VM의 IP, CPU와 다름 |
| **배포 센터** | GitHub, Azure DevOps 연동 자동 배포 | VM에는 없음 |
| **구성** | 환경 변수, 연결 문자열 설정 | OS 레지스트리 대신 |
| **스케일 업** | App Service 플랜 크기 변경 | VM 크기 변경과 유사 |
| **스케일 아웃** | 인스턴스 수 자동 증가 | VM에서는 수동 구성 필요 |
| **배포 슬롯** | 스테이징 환경 별도 운영 | Standard 이상 사용 가능 |

### 3-2. OS 관련 설정 없음 확인

1. 왼쪽 메뉴를 전체적으로 스크롤합니다.
2. VM과 달리 아래 항목들이 **없음**을 확인합니다.
   - OS 업데이트/패치 설정
   - 디스크 관리
   - 네트워크 인터페이스 직접 관리

!!! tip "PaaS의 핵심 장점"
    VM(IaaS)에서는 개발자가 직접 해야 했던 일들을 Azure가 대신합니다.

    | 작업 | IaaS(VM) | PaaS(App Service) |
    |------|----------|-------------------|
    | OS 설치 | 직접 | Azure 자동 |
    | OS 보안 패치 | 직접 | Azure 자동 |
    | 웹 서버(Nginx 등) 설치 | 직접 | Azure 자동 |
    | SSL 인증서 관리 | 직접 구성 | 무료 자동 갱신 |
    | 고가용성 구성 | 직접 구성 | 플랜에 포함 |

### 3-3. 구성 메뉴 탐색

1. 왼쪽 메뉴에서 **구성**을 클릭합니다.
2. **애플리케이션 설정** 탭에서 환경 변수를 추가할 수 있음을 확인합니다.
3. **일반 설정** 탭에서 PHP/Node 버전을 변경할 수 있음을 확인합니다.

!!! tip "팁"
    App Service에서는 런타임 버전(PHP 8.2 → PHP 8.3 등)을
    클릭 몇 번으로 변경할 수 있습니다.
    VM에서는 직접 SSH 접속 후 패키지를 교체해야 합니다.

### 3-4. 스케일 아웃 확인

1. 왼쪽 메뉴에서 **스케일 아웃(App Service 플랜)** 을 클릭합니다.
2. Free F1 플랜은 스케일 아웃이 제한됨을 확인합니다.
3. Standard 이상에서는 CPU 사용률에 따라 자동으로 인스턴스가 증가하는 **자동 스케일링** 설정이 가능합니다.

## 핵심 정리

1. **PaaS는 OS와 인프라 관리 부담을 Azure가 담당**합니다.
   개발자는 코드와 데이터에만 집중할 수 있어 생산성이 크게 향상됩니다.
   IaaS 대비 관리 범위가 줄어드는 만큼 유연성도 일부 제한됩니다.

2. **App Service 플랜이 실제 컴퓨팅 자원을 결정**합니다.
   하나의 플랜 위에 여러 App Service 앱을 올릴 수 있으며,
   플랜의 크기(요금 계층)에 따라 성능과 기능이 달라집니다.

3. **URL은 전 세계 고유하며 HTTPS가 기본 제공**됩니다.
   VM에서 직접 웹 서버를 구성하면 SSL 인증서를 별도로 발급해야 하지만,
   App Service는 `*.azurewebsites.net` 도메인에 HTTPS가 자동 적용됩니다.
