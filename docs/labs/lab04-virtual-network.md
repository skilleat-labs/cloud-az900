# Lab 04 · 가상 네트워크 만들기

!!! info "실습 정보"
    - **주제**: Azure 네트워킹 기초
    - **예상 시간**: 15분
    - **배우는 것**:
        1. Azure 가상 네트워크(VNet)와 서브넷 구성 방법
        2. CIDR 표기법으로 IP 주소 범위를 설정하는 방법
        3. 네트워크 보안 그룹(NSG)의 역할과 기본 규칙

!!! warning "사전 준비"
    Lab 01에서 만든 리소스 그룹 `rg-[본인이름]-lab`이 있어야 합니다.

---

## 실습 목표

Azure에서 VM이나 기타 서비스들이 서로 통신하려면 **가상 네트워크(VNet)** 가 필요합니다.
VNet은 온프레미스의 사설 네트워크를 클라우드에 구현한 것입니다.
이번 실습에서는 VNet과 서브넷을 만들고, 네트워크 보안 그룹(NSG)을 탐색합니다.

---

## Step 1 · 가상 네트워크 만들기

> Azure Portal → 검색창 → "가상 네트워크" → 만들기

### 1-1. 가상 네트워크 검색

1. Azure Portal 상단 **검색창**에 `가상 네트워크`를 입력합니다.
2. 검색 결과에서 **가상 네트워크**를 클릭합니다.
3. **+ 만들기** 버튼을 클릭합니다.

### 1-2. 기본 사항 탭 설정

| 항목 | 값 |
|------|-----|
| 구독 | 강사가 제공한 구독 선택 |
| 리소스 그룹 | `rg-[본인이름]-lab` |
| 이름 | `vnet-[본인이름]-lab` (예: `vnet-gildong-lab`) |
| 지역 | Korea Central |

---

## Step 2 · IP 주소 설정

### 2-1. IP 주소 탭으로 이동

1. 상단의 **IP 주소** 탭을 클릭합니다.

### 2-2. 주소 공간 확인

1. **주소 공간** 항목에서 기본값 `10.0.0.0/16`을 확인합니다.
2. 이 VNet 안에서 사용할 수 있는 IP 주소 범위를 의미합니다.

!!! tip "CIDR 표기법 이해"
    `10.0.0.0/16`은 다음을 의미합니다:
    - 네트워크 시작 IP: `10.0.0.0`
    - 사용 가능한 IP 수: **65,536개** (2^16)
    - 범위: `10.0.0.0` ~ `10.0.255.255`

    `/16`은 앞의 16비트가 네트워크 주소임을 나타냅니다.
    숫자가 클수록 더 작은 네트워크(IP 수 적음)입니다.
    - `/16` → 65,536개
    - `/24` → 256개
    - `/28` → 16개

### 2-3. 기본 서브넷 확인

1. **서브넷** 목록에서 자동으로 생성된 기본 서브넷을 확인합니다.
2. **default** 서브넷의 주소 범위 `10.0.0.0/24`를 확인합니다.
3. 이 서브넷은 256개의 IP를 사용할 수 있습니다.

### 2-4. 백엔드 서브넷 추가

> 실제 아키텍처에서는 계층(프론트엔드, 백엔드, DB)별로 서브넷을 분리합니다.

1. **+ 서브넷 추가** 버튼을 클릭합니다.
2. 오른쪽에 서브넷 추가 패널이 열립니다.
3. 아래 정보를 입력합니다.

| 항목 | 값 |
|------|-----|
| 서브넷 이름 | `subnet-backend` |
| 시작 주소 | `10.0.1.0` |
| 서브넷 크기 | `/24` (256개 주소) |

4. **추가** 버튼을 클릭합니다.

!!! tip "서브넷 설계 원칙"
    서브넷을 계층별로 분리하면 보안을 강화할 수 있습니다.
    예시:
    - `subnet-frontend`: 10.0.0.0/24 (웹 서버)
    - `subnet-backend`: 10.0.1.0/24 (애플리케이션 서버)
    - `subnet-database`: 10.0.2.0/24 (데이터베이스 서버)

    각 서브넷에 NSG를 연결하여 계층 간 트래픽을 제어합니다.

---

## Step 3 · 만들기 및 탐색

### 3-1. VNet 생성

1. **검토 + 만들기** 탭을 클릭합니다.
2. 설정 내용을 검토합니다.
3. **만들기** 버튼을 클릭합니다.
4. 배포 완료 후 **리소스로 이동**을 클릭합니다.

!!! success "완료"
    가상 네트워크가 성공적으로 생성되었습니다.

### 3-2. VNet 개요 탐색

VNet 개요 페이지에서 다음을 확인합니다.

1. **주소 공간**: `10.0.0.0/16` 표시 확인
2. **DNS 서버**: Azure 제공 기본 DNS 사용 중

### 3-3. 서브넷 확인

1. 왼쪽 메뉴에서 **서브넷**을 클릭합니다.
2. 서브넷 목록에서 2개의 서브넷을 확인합니다.

| 서브넷 이름 | 주소 범위 | 용도 |
|------------|----------|------|
| default | 10.0.0.0/24 | 기본 서브넷 |
| subnet-backend | 10.0.1.0/24 | 백엔드 서버용 |

3. 각 서브넷의 **연결된 디바이스** 열이 비어 있는 것을 확인합니다.
   (VM을 이 VNet에 연결하면 여기에 표시됩니다.)

### 3-4. 피어링 탐색

1. 왼쪽 메뉴에서 **피어링**을 클릭합니다.
2. 현재 피어링된 VNet이 없음을 확인합니다.

!!! tip "VNet 피어링이란?"
    서로 다른 VNet(또는 서로 다른 지역의 VNet)끼리 연결하는 기능입니다.
    피어링을 설정하면 두 VNet의 리소스가 같은 네트워크처럼 통신할 수 있습니다.
    예: Korea Central의 VNet과 Japan East의 VNet을 피어링

---

## Step 4 · 네트워크 보안 그룹(NSG) 만들기

> NSG는 클라우드의 방화벽으로, 인바운드/아웃바운드 트래픽을 포트 단위로 제어합니다.

### 4-1. NSG 만들기

> Azure Portal → 검색창 → "네트워크 보안 그룹" → 만들기

1. 상단 **검색창**에 `네트워크 보안 그룹`을 입력합니다.
2. **네트워크 보안 그룹**을 클릭합니다.
3. **+ 만들기** 버튼을 클릭합니다.

| 항목 | 값 |
|------|-----|
| 구독 | 강사가 제공한 구독 선택 |
| 리소스 그룹 | `rg-[본인이름]-lab` |
| 이름 | `nsg-[본인이름]-lab` |
| 지역 | Korea Central |

4. **검토 + 만들기** → **만들기**를 클릭합니다.
5. 배포 완료 후 **리소스로 이동**을 클릭합니다.

### 4-2. 기본 규칙 탐색

1. 왼쪽 메뉴에서 **인바운드 보안 규칙**을 클릭합니다.
2. 기본으로 생성된 규칙들을 확인합니다.

| 규칙 이름 | 우선 순위 | 포트 | 동작 | 설명 |
|-----------|----------|------|------|------|
| AllowVnetInBound | 65000 | 모든 포트 | 허용 | VNet 내부 트래픽 허용 |
| AllowAzureLoadBalancerInBound | 65001 | 모든 포트 | 허용 | Azure 로드 밸런서 허용 |
| DenyAllInBound | 65500 | 모든 포트 | 거부 | 그 외 모든 트래픽 차단 |

3. **아웃바운드 보안 규칙**도 클릭하여 기본 규칙을 확인합니다.

!!! tip "NSG 규칙 이해"
    NSG 규칙은 **우선 순위(Priority)** 가 낮을수록 먼저 적용됩니다.
    - 100이 65000보다 먼저 평가됨
    - 규칙에 매칭되면 이후 규칙은 평가하지 않음

    예시: HTTP(80) 포트를 허용하려면
    우선 순위 100번에 포트 80 **허용** 규칙을 추가하면 됩니다.

### 4-3. 인바운드 규칙 추가 (선택 실습)

HTTP 트래픽을 허용하는 규칙을 추가해봅니다.

1. **+ 추가** 버튼을 클릭합니다.
2. 아래 정보를 입력합니다.

| 항목 | 값 |
|------|-----|
| 소스 | Any |
| 소스 포트 범위 | * |
| 대상 | Any |
| 대상 포트 범위 | 80 |
| 프로토콜 | TCP |
| 작업 | 허용 |
| 우선 순위 | 100 |
| 이름 | Allow-HTTP |

3. **추가** 버튼을 클릭합니다.
4. 규칙 목록에 Allow-HTTP가 추가된 것을 확인합니다.

## 완료 확인 체크리스트

- [ ] `vnet-[본인이름]-lab` 가상 네트워크가 생성되었다
- [ ] 주소 공간이 `10.0.0.0/16`으로 설정되어 있다
- [ ] `default`와 `subnet-backend` 2개의 서브넷이 있다
- [ ] `nsg-[본인이름]-lab` 네트워크 보안 그룹이 생성되었다

## 실습 정리

!!! danger "비용 주의"
    가상 네트워크 자체는 무료이지만,
    공용 IP 주소나 VPN 게이트웨이는 비용이 발생합니다.
    이번 실습에서는 공용 IP를 생성하지 않았으므로 추가 비용이 없습니다.

**VNet 및 NSG 삭제 방법:**

리소스 그룹(`rg-[본인이름]-lab`)에서 아래 리소스를 선택하여 삭제합니다:
- `vnet-[이름]-lab`
- `nsg-[이름]-lab`

또는 모든 실습 완료 후 리소스 그룹 전체를 삭제합니다.

---

## 핵심 정리

1. **VNet은 Azure에서 리소스 간 통신을 위한 사설 네트워크**입니다.
   VM, App Service(프리미엄), Database 등이 VNet에 연결되어 외부에 노출 없이 통신할 수 있습니다.
   서브넷으로 네트워크를 논리적으로 분리하여 보안을 강화합니다.

2. **서브넷은 VNet 내의 작은 네트워크 구역**입니다.
   프론트엔드/백엔드/DB 계층별로 서브넷을 분리하고
   각 서브넷에 NSG를 연결하여 계층 간 접근을 제어하는 것이 모범 사례입니다.

3. **NSG는 포트 기반 방화벽으로 인바운드/아웃바운드 트래픽을 제어**합니다.
   우선 순위가 낮은 규칙이 먼저 적용되며,
   마지막에 항상 "모든 트래픽 차단" 규칙이 있어 명시적으로 허용한 것만 통과합니다.
