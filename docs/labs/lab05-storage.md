# Lab 05 · 스토리지 계정 만들기

!!! info "실습 정보"
    - **주제**: Azure 스토리지 서비스
    - **예상 시간**: 15분
    - **배우는 것**:
        1. Azure 스토리지 계정 생성 및 Blob 스토리지 사용 방법
        2. 중복성 옵션(LRS, GRS, ZRS)의 차이
        3. Hot/Cool/Archive 액세스 계층의 특징과 비용 차이

!!! warning "사전 준비"
    Lab 01에서 만든 리소스 그룹 `rg-[본인이름]-lab`이 있어야 합니다.

---

## 실습 목표

Azure 스토리지는 대용량 데이터를 저장하는 클라우드 스토리지 서비스입니다.
이번 실습에서는 스토리지 계정을 만들고, Blob 컨테이너에 파일을 업로드하여
퍼블릭 URL로 접근하는 과정을 체험합니다.

---

## Step 1 · 스토리지 계정 만들기

> Azure Portal → 검색창 → "스토리지 계정" → 만들기

### 1-1. 스토리지 계정 검색

1. Azure Portal 상단 **검색창**에 `스토리지 계정`을 입력합니다.
2. 검색 결과에서 **스토리지 계정**을 클릭합니다.
3. **+ 만들기** 버튼을 클릭합니다.

### 1-2. 기본 사항 탭 설정

**프로젝트 세부 정보:**

| 항목 | 값 |
|------|-----|
| 구독 | 강사가 제공한 구독 선택 |
| 리소스 그룹 | `rg-[본인이름]-lab` |

**인스턴스 세부 정보:**

| 항목 | 값 |
|------|-----|
| 스토리지 계정 이름 | `st[본인이름]lab` (예: `stgildonglab`) |
| 지역 | Korea Central |
| 성능 | 표준 |
| 중복성 | LRS(로컬 중복 스토리지) |

!!! warning "스토리지 계정 이름 규칙"
    스토리지 계정 이름은 다음 규칙을 따라야 합니다:
    - **전 세계에서 고유**해야 합니다
    - **소문자와 숫자만** 사용 가능 (하이픈, 언더스코어 불가)
    - **3~24자** 이내

    예시: `stgildong2024` (st + 이름 + 연도)

!!! tip "중복성(Redundancy) 옵션 이해"
    | 옵션 | 전체 이름 | 복제 방식 | 비용 |
    |------|-----------|----------|------|
    | LRS | 로컬 중복 스토리지 | 같은 데이터센터 내 3개 복제 | 저렴 |
    | ZRS | 영역 중복 스토리지 | 같은 지역 내 3개 가용성 영역에 복제 | 중간 |
    | GRS | 지역 중복 스토리지 | 기본 지역 3개 + 보조 지역 3개 복제 | 비쌈 |
    | GZRS | 지역 영역 중복 | ZRS + GRS 결합 | 가장 비쌈 |

    실습에서는 비용이 가장 낮은 **LRS**를 사용합니다.

## Step 2 · Blob 컨테이너 만들기

### 2-1. 스토리지 계정 생성 완료

1. **검토 + 만들기** 버튼을 클릭합니다.
2. 설정을 검토한 후 **만들기**를 클릭합니다.
3. 배포 완료 후 **리소스로 이동**을 클릭합니다.

!!! success "완료"
    스토리지 계정이 생성되었습니다.

### 2-2. 컨테이너 만들기

> 스토리지 계정 → 왼쪽 메뉴 → 컨테이너

1. 왼쪽 메뉴에서 **컨테이너**를 클릭합니다.
2. **+ 컨테이너** 버튼을 클릭합니다.
3. 오른쪽에 새 컨테이너 패널이 열립니다.
4. 아래 정보를 입력합니다.

| 항목 | 값 |
|------|-----|
| 이름 | `myfiles` |
| 공개 액세스 수준 | Blob(Blob에 대한 익명 읽기 전용 액세스) |

5. **만들기** 버튼을 클릭합니다.

!!! tip "공개 액세스 수준 이해"
    | 수준 | 설명 |
    |------|------|
    | 프라이빗(기본) | 인증된 사용자만 접근 가능 |
    | Blob | 개별 파일 URL로 익명 접근 가능 |
    | 컨테이너 | 컨테이너 내 파일 목록 및 파일 모두 공개 |

    이번 실습에서는 **Blob** 수준을 사용하여 파일 URL로 직접 접근합니다.

## Step 3 · 파일 업로드 및 URL 접근

### 3-1. 파일 업로드

1. 컨테이너 목록에서 **myfiles**를 클릭합니다.
2. 빈 컨테이너 화면이 표시됩니다.
3. 상단의 **업로드** 버튼을 클릭합니다.
4. 오른쪽 업로드 패널에서 **파일 찾아보기**를 클릭합니다.
5. 본인 PC에서 작은 이미지 파일(JPG, PNG) 또는 텍스트 파일을 선택합니다.
6. **업로드** 버튼을 클릭합니다.

!!! tip "테스트 파일 준비"
    업로드할 파일이 없으면 메모장(Notepad)에서 텍스트를 작성하고
    `test.txt`로 저장하여 업로드해도 됩니다.

### 3-2. 업로드된 파일 확인 및 URL 접근

1. 컨테이너 목록에 업로드한 파일이 표시되는 것을 확인합니다.
2. 파일 이름을 **클릭**합니다.
3. 파일 속성 패널에서 **URL** 항목을 찾습니다.
4. URL 형식:
   ```
   https://[스토리지계정이름].blob.core.windows.net/myfiles/[파일명]
   ```
5. URL 오른쪽의 **복사 아이콘**을 클릭합니다.
6. 브라우저 새 탭에 붙여넣기하여 파일에 접근합니다.

!!! success "완료"
    브라우저에서 업로드한 파일(이미지 또는 텍스트)이 표시되면 성공입니다.
    Azure Blob Storage에 업로드된 파일이 퍼블릭 URL로 제공되고 있습니다.

### 3-3. 파일 속성 탐색

파일 속성 패널에서 다음 정보를 확인합니다.

| 항목 | 설명 |
|------|------|
| URL | 파일 접근 주소 |
| 마지막 수정 날짜 | 업로드된 시간 |
| 크기 | 파일 크기 |
| Blob 유형 | 블록 Blob (일반 파일) |
| 액세스 계층 | Hot (기본값) |

## Step 4 · 액세스 계층 확인

> 데이터 접근 빈도에 따라 스토리지 비용을 최적화할 수 있습니다.

### 4-1. 액세스 계층 이해

!!! tip "Hot / Cool / Archive 계층"
    | 계층 | 용도 | 스토리지 비용 | 접근 비용 |
    |------|------|-------------|---------|
    | **Hot** | 자주 접근하는 데이터 | 높음 | 낮음 |
    | **Cool** | 가끔 접근 (30일 이상 보관) | 낮음 | 중간 |
    | **Cold** | 드물게 접근 (90일 이상 보관) | 더 낮음 | 높음 |
    | **Archive** | 거의 접근 안 함 (180일 이상) | 가장 낮음 | 매우 높음 (복원 필요) |

    실제 활용 예시:
    - **Hot**: 웹사이트 이미지, 자주 다운로드되는 파일
    - **Cool**: 월간 보고서, 백업 파일
    - **Archive**: 수년 전 로그 파일, 법적 보존 데이터

### 4-2. 수명 주기 관리 탐색

1. 왼쪽 메뉴에서 **수명 주기 관리**를 클릭합니다.
2. **+ 규칙 추가** 버튼을 확인합니다.

!!! tip "수명 주기 관리(Lifecycle Management)"
    조건에 따라 자동으로 파일을 계층 이동하거나 삭제하는 규칙을 설정할 수 있습니다.

    예시 규칙:
    - 생성 후 30일이 지난 파일 → Hot에서 Cool로 자동 이동
    - 생성 후 90일이 지난 파일 → Cool에서 Archive로 자동 이동
    - 생성 후 365일이 지난 파일 → 자동 삭제

    이를 통해 스토리지 비용을 자동으로 최적화할 수 있습니다.

### 4-3. 스토리지 서비스 종류 탐색

1. 왼쪽 메뉴를 스크롤하여 다양한 스토리지 서비스를 확인합니다.

| 메뉴 | 서비스 | 용도 |
|------|--------|------|
| 컨테이너 | Blob Storage | 이미지, 동영상, 문서 등 비정형 데이터 |
| 파일 공유 | Azure Files | SMB 파일 공유 (네트워크 드라이브처럼 사용) |
| 큐 | Queue Storage | 메시지 큐, 비동기 처리 |
| 테이블 | Table Storage | NoSQL 형태의 구조화 데이터 |

## 핵심 정리

1. **Azure Blob Storage는 대용량 비정형 데이터 저장에 최적화**되어 있습니다.
   이미지, 동영상, 로그 파일, 백업 데이터 등을 저렴하게 저장할 수 있으며,
   퍼블릭 URL을 통해 전 세계 어디서나 접근할 수 있습니다.

2. **중복성 옵션은 데이터 내구성과 비용의 트레이드오프**입니다.
   LRS는 가장 저렴하지만 단일 데이터센터 장애에 취약하고,
   GRS는 지역 재해 발생 시에도 데이터를 보존하지만 비용이 높습니다.
   99.9999999% (11 9's) 내구성을 기본으로 제공합니다.

3. **액세스 계층과 수명 주기 관리로 스토리지 비용을 최적화**할 수 있습니다.
   자주 사용하지 않는 데이터를 자동으로 Cool 또는 Archive 계층으로 이동하면
   스토리지 비용을 최대 90%까지 절감할 수 있습니다.
